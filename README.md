# Rightium — website + CMS

Next.js 16 (App Router) · Payload CMS 3 · Tailwind v4 · Motion. Hosted on **Vercel**,
with the database on **Neon** (Postgres) and uploaded images on **Cloudflare R2**.

## Current status: preview mode

The site deploys and runs with **no configuration at all**. Until `DATABASE_URI` is set:

- Insights show the built-in launch articles (`src/seed/insights.ts`).
- `/admin`, the Payload API and draft preview return 404 (`src/proxy.ts`).
- The contact form validates and responds; enquiries are emailed if `RESEND_API_KEY`
  is set, otherwise only logged. **Nothing is stored yet.**
- Search engines are blocked: `robots.txt` disallows everything, every page has
  `noindex, nofollow`, and every response (images too) carries `X-Robots-Tag: noindex`.
  Set `ALLOW_INDEXING=true` and redeploy only at launch.

## Deploy the preview to Vercel

1. Push this repository to GitHub (private is fine).
2. On vercel.com: **Add New → Project → Import** the repository. Vercel detects Next.js;
   keep the defaults (build command comes from `package.json`).
3. No environment variables are needed for the preview. Click **Deploy**.
4. Share the `https://<project>.vercel.app` URL with the client.

Every push to the main branch redeploys automatically. Pushes to other branches get
their own preview URLs (Vercel also marks those `noindex`).

## Run locally

```bash
npm install
npm run dev        # http://localhost:3000 (preview mode until DATABASE_URI is set)
npm run build && npm start   # production build, as Vercel runs it
npm run typecheck
npm run lint
```

## Backend (next step)

Payload is already configured for Neon + R2 (`src/payload.config.ts`); switching it on is:
creating the Neon database and R2 bucket, setting the variables in `.env.example`,
generating the first Postgres migration (and re-adding the launch-articles seed from
`src/seed/seed-insights.ts`), and running migrations as part of the Vercel build.

After changing a collection in `src/collections/`:

```bash
npm run migrate:create <name>   # writes a migration to src/migrations/
npm run generate:types          # refreshes src/payload-types.ts
npm run generate:importmap      # only if you added admin components
```

### Analytics events

PostHog records page views and clicks automatically, plus these named events for
conversion reporting: `enquiry_submitted` (with service and deadline), `enquiry_failed`,
and `contact_click` (`channel`: phone, email, whatsapp or map). Analytics are off when
`NEXT_PUBLIC_POSTHOG_KEY` is empty, on `/admin`, and for browsers with Do Not Track on.

### Design system

Dark-first. The midnight-indigo gradient (kept from the first build at the client's
request) carries the brand on alternating dark sections; light sections carry the reading.
Tokens live in the `:root` block of `globals.css`:

| Token | Value | Use |
| --- | --- | --- |
| `--deep` → `--deep-4` | `#020108` → `#2a14a8` | Dark sections, hero, footer |
| `--accent` / `--accent-bright` | `#3a1fd6` / `#8a7bff` | Electric indigo / periwinkle highlight |
| `--paper` / `--surface` | `#fff` / `#f5f6fb` | Light sections |
| `--r-pill` / `--r-card` / `--r-block` | 100px / 24px / 36px | Buttons / cards / large blocks |

Type is **Manrope** (display) over **Inter** (body), both via `next/font`.

Every photo runs through the `.duotone` class (grayscale + brand-gradient `color` blend),
so stock from different shoots reads as one set. Add `.duotone-soft` on light sections.
Swapping a photo is just replacing the file; the treatment follows.

## Motion

Tokens: `--ease-out: cubic-bezier(0.23, 1, 0.32, 1)`, `--ease-in-out: cubic-bezier(0.77, 0, 0.175, 1)`.
UI interactions stay under 300ms; marketing reveals run 600–900ms. Everything animates
`transform`/`opacity` only (the accordion's height is the single documented exception).

`prefers-reduced-motion` degrades to fades rather than to nothing, and every hover effect is
gated behind `@media (hover: hover) and (pointer: fine)` so touch taps do not strand them.
